Проект создан в рамках учебной практики в университете Синергия

# Анализ информационных систем, построенных по архитектуре WEB-приложений

## 1. Введение

Веб-приложение - это информационная система, которой пользователь может пользоваться через веб-браузер. Обычно она состоит из пользовательского интерфейса, веб-сервера, серверной части приложения и базы данных.

Общую схему можно представить следующим образом:

**Пользователь - Веб-браузер - Веб-сервер - Веб-приложение - База данных**

Пользователь выполняет действие на сайте, браузер отправляет запрос на сервер, приложение обрабатывает его и при необходимости обращается к базе данных. После этого результат возвращается пользователю.


## 2. Принцип работы Веб-приложения

Веб-приложение можно разделить на две основные части:

* **Front-end** - клиентская часть;
* **Back-end** - серверная часть.

### Front-end

Front-end - это часть приложения, которую видит пользователь. Она отвечает за страницы, кнопки, формы, меню, каталог и отображение информации.

Для создания Front-end используются HTML, CSS, JavaScript и различные фреймворки.

### Back-end

Back-end работает на сервере. Он отвечает за обработку запросов, выполнение логики приложения, проверку данных и работу с базой данных.

Например, при поиске товара пользователь вводит его название в поисковую строку. Браузер отправляет запрос серверу, приложение получает данные из базы и возвращает найденные товары.

## 3. Уровни архитектуры Веб-приложений

Можно выделить несколько основных уровней:

* **Presentation Layer (PL)** - уровень представления;
* **Business Logic Layer (BLL)** - бизнес-логика;
* **Data Service Layer (DSL)** - службы данных;
* **Data Access Layer (DAL)** - доступ к данным.

### Уровень представления

Отвечает за интерфейс пользователя: страницы, кнопки, каталог, категории и поиск.

В моем проекте TechShop к нему относятся главная страница, каталог товаров, категории и страницы с информацией о товарах.

### Уровень бизнес-логики

Отвечает за основные действия приложения: поиск, фильтрацию, проверку наличия товаров и обработку заказов.

### Уровень служб данных

Обеспечивает передачу данных между серверной частью и другими уровнями приложения.

### Уровень доступа к данным

Отвечает за работу с базой данных. Основные операции с данными:

* **Create** - создание;
* **Read** - чтение;
* **Update** - изменение;
* **Delete** - удаление.

## 4. Основные типы WEB-архитектур

Основными видами WEB-архитектуры являются:

* SPA - одностраничные приложения;
* MPA - многостраничные приложения;
* микросервисная архитектура;
* бессерверная архитектура;
* PWA - прогрессивные веб-приложения.

### SPA

SPA (Single Page Application) - приложение, в котором основная страница загружается один раз, а содержимое изменяется динамически.

**Преимущества:**

* высокая интерактивность;
* быстрое изменение содержимого;
* удобство для сложных систем.

**Недостаток:** разработка может быть сложнее из-за большого количества клиентской логики.

SPA часто используется для CRM-систем, личных кабинетов, аналитических панелей и корпоративных приложений.

### MPA

MPA (Multi-Page Application) состоит из нескольких отдельных страниц. При переходе на другую страницу браузер отправляет новый запрос серверу.

**Преимущества:**

* относительно простая структура;
* хорошо подходит для информационных сайтов и интернет-магазинов.

**Недостаток:** при переходе между страницами происходит их повторная загрузка.

### Микросервисная архитектура

Микросервисная архитектура - приложение, разделенное на несколько небольших независимых сервисов. Каждый сервис отвечает за отдельную функцию.

**Преимущества:**

*отдельные части можно изменять независимо;
*удобно масштабировать систему;
*подходит для крупных проектов.

**Недостаток:** разработка и настройка такой системы сложнее.

Используется в крупных интернет-магазинах, банковских и корпоративных системах.

## Бессерверная архитектура

Бессерверная архитектура (Serverless) позволяет запускать отдельные функции без самостоятельного управления серверами.

**Преимущества:**

не нужно самостоятельно обслуживать сервер;
автоматическое масштабирование;
удобно для отдельных задач.

**Недостаток:** зависимость от облачного провайдера.

Используется для обработки запросов, загрузки файлов, отправки уведомлений и других задач.

## PWA

PWA (Progressive Web Application) - веб-приложение, которое по своим возможностям может напоминать обычное мобильное приложение.

**Преимущества:**

работает через браузер;
можно установить на устройство;
некоторые функции могут работать без постоянного подключения к интернету.

**Недостаток:** возможности зависят от поддержки браузера.

PWA используется в интернет-магазинах, сервисах доставки, образовательных и корпоративных приложениях.

## 5. Современные фреймворки

Для разработки WEB-приложений используются различные фреймворки.

### Front-end

**React** - популярная технология для создания интерактивных интерфейсов. Ее преимуществами являются большое сообщество и большое количество библиотек.

**Vue.js** - достаточно простой и гибкий фреймворк, который подходит для небольших и средних проектов.

**Angular** - более сложный фреймворк на TypeScript, который часто применяется в крупных корпоративных системах.

### Back-end

**Django** -фреймворк на Python, подходящий для интернет-магазинов, информационных систем и API.

**Node.js + Express** - технология для создания серверных приложений и API. Позволяет использовать JavaScript как на клиентской, так и на серверной стороне.

**Spring Boot** - фреймворк на Java, который часто применяется для крупных корпоративных приложений и микросервисов.

### Full-stack

**Laravel** - PHP-фреймворк для разработки веб-сайтов, интернет-магазинов, CMS и корпоративных систем.
